# solace-healthcheck-utility

Browser tool that turns Solace PubSub+ software-broker diagnostics (`cli-diagnostics.txt` from
gather-diagnostics, optional current-config export, optional CLI transcript) into the Ops
Readiness Checklist workbook with a Pass / Warning / Fail verdict per check and per broker.
Everything runs client-side; no build tooling beyond Node.

This file holds the conventions that apply to every task here. It extends the global golden
rules; on conflict the global order applies (security → correctness → these conventions → style).
Mechanics live in `docs/architecture.md` (module map, analyzer contract, add-a-check) and
`docs/developer-guide.md` (workflow, tests, troubleshooting). Read the relevant section before
changing a subsystem.

## Layout in one glance

- `src/*.js` — ES modules, the source of truth. Pure except `ui.js` and `main.js`.
- `app.js` — GENERATED by `scripts/build.mjs`. Never edit; never commit a stale one.
- `index.html`, `styles.css` — shell and Solace 2025 theme (tokens at the top of the CSS).
- `scripts/dev.sh` / `dev.ps1` — mirrored task runners: `build`, `lint`, `test`, `all`, `serve`.
- `test/*.test.js`, `test/fixtures/` — node:test suites and anonymised sample inputs.
- `run-healthcheck.sh` — launcher (build + serve/open). `legacy/` — old implementation, read-only.

## Gates (ask, don't run)

After any change under `src/`, `test/`, `scripts/` or `index.html`, hand off with:

```
./scripts/dev.sh all      # build app.js + lint (module load, bundle syntax) + tests
```

Read `scripts/logs/<task>.log` for results. Generating `app.js` is part of authoring the
deliverable and may be run when the page cannot work without it; lint and tests are the user's.
Never run `run-healthcheck.sh --check` yourself: it runs the gates.

## Hard rules

- **Bundle constraints.** Only relative `./x.js` imports and named `export function|const|let|class`.
  Top-level identifiers must be unique across all modules. Keep the dependency order
  `sections → checks → config-parser → broker → analyzers → checklist → xlsx → report → ui → main`;
  lower modules never import higher ones. Update `ORDER` in `scripts/build.mjs` when adding a module.
- **DOM only in `ui.js`/`main.js`**, scoped to the root passed to `createApp`. Every other module
  must load and run in Node.
- **Analyzers** return `result(status, output, note)` or `null` (fall back to the default outcome).
  Use `STATUS` values only; never invent a new status string without updating `STATUS_LABEL`,
  `STATUS_ORDER`, the UI pills and `STATUS_STYLE` in `report.js` in the same change.
- **Evidence is read from sections, not guessed.** Prefer `valueOf`, `counterOf`, `blockBetween`,
  `parseFixedTable` over whole-body regexes. Verdicts: Warning = needs a look, Fail = evidence
  contradicts the expectation, Info = captured but design-dependent, N/A = role/feature not applicable.
- **Role awareness.** HA-pair checks must return `na` for Monitor and Standalone nodes.
- **Dates.** Certificate and age calculations use the diagnostics snapshot (`profile.snapshot`),
  falling back to `ctx.now`; say which one applied in the output.
- **Secrets.** Config redaction happens in `parseConfig` (`redactLine`). Never bypass it, never log
  credentials, never put a real password in a fixture.
- **Fixtures stay anonymised.** No customer hostnames, IPs, organisation names or certificate
  serials. Real bundles are for manual checks only and must not be copied into the repo.
- **Docs in sync.** A change to inputs, verdict rules, statuses, dev-script tasks or the build
  updates `README.md` and the relevant `docs/*.md` in the same change.
- **Tests with the change.** New or changed analyzer → fixture section + assertion in
  `test/analyzers.test.js`. New parser behaviour → assertion in the matching suite.

## Adding a check (short form)

Row in `src/checks.js` (unique `ref`, `commands` with `|` alternatives) → analyzer in
`src/analyzers.js` → add the command to `GATHER_DIAGNOSTICS_COMMANDS` only if the standard bundle
produces it → fixture section + test → `./scripts/dev.sh all`.

## Style

- Plain modern JS, no dependencies, no transpiling. Two-space indent, double quotes, semicolons.
- Match the existing analyzer shape and helper usage; do not add a second way to do the same thing.
- UI text is terse and operational; keep "Solace Ops Readiness Checklist" as the displayed title.
- CSS: reuse the `--sol-*` and `--sem-*` tokens; Fail uses the soft red deliberately.
